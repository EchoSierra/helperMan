## Open

- **Add the three approved master-data CSV exports.** Export helpers with organization, equipment, and qualifications (no contact details), all equipment, and all qualifications; neutralize spreadsheet formulas and audit each download.
- **Apply migrations to the eventual target database.** Eight migrations are applied and current on the dev and test databases. Before applying them to any other target, confirm its identity and state, inventory existing legacy rows, approve a lossless classification/mapping for legacy `User` data, review/backup, and apply through the deployment process with `prisma migrate deploy`. Do not assume legacy people rows are accounts or vice versa.
- **Verify audit acceptance criteria.** Align persisted audit events with the approved minimal actor/action/target/time shape; cover authentication, MFA, account/role, report, helper, and qualification activity. Make writes and their audit events atomic, fail closed for reads if audit persistence fails, and ensure events contain no field values, PII, IP addresses, credentials, or secrets, except the specifically approved old/new qualification valid-through date values and fixed sentinels.
- **Extend PostgreSQL integration coverage.** `npm run test:integration` (separate `*_test` database) (safety: `setup-env.ts` pins `DATABASE_URL` to `TEST_DATABASE_URL` before any import and refuses names without `test`) now covers account administration, helper and qualification CRUD, catalog and equipment lifecycles, partial uniqueness, migration compatibility, role denial, audited reads/writes, fail-closed reads, atomic audit rollback, and password/TOTP flows. Still open: broader audit-view, migration and retention acceptance coverage using synthetic data only.
- **Approve no-other-Administrator recovery.** The operator break-glass script `npm run auth:recover-admin` is implemented, audited (`ADMIN_RECOVERED`), integration-tested and documented in the README; it keeps TOTP re-enrollment mandatory. Still open: the organization's approval of who may run it and how identity is verified, i.e. an approved operational procedure that preserves mandatory TOTP re-enrollment and does not grant protected access before re-enrollment.
- **Complete production operational readiness.** Obtain formal approval for both helper and audit retention schedules and record them at `/admin/retention`; schedule `npm run retention:run`; provision at least two verified Administrators with completed TOTP; verify the production preflight; and complete production migration review, encrypted backup/restore testing, TLS/private database configuration, monitoring, and deployment ownership. Production use remains blocked until the required approvals and account readiness are verified.
- **Close release security review follow-ups.** Review done: one medium finding (spoofable `X-Forwarded-For` bypassing the sign-in rate limit) fixed via `TRUSTED_PROXIES` plus a preflight blocker. Remaining recommendation: hash session tokens at rest. Shared rate-limit storage is deferred because the deployment is intentionally single-instance; revisit before scaling out and re-review after production configuration.

## Done

- **Add reusable organizations and an optional helper organization.** New `organizations` table and nullable `helpers.organizationId` (migration `20261016100000_organizations`, applied to dev and test), Maintainer-only `/organizations` management (unique case-insensitive name, retire without deleting), organization select on the helper form, display on the profile, `ORGANIZATION_CREATED/UPDATED` audit events, and integration tests. The helper-with-equipment-and-qualifications export includes the organization name; contact details remain excluded.
- **Apply cohesive UI styling across the MVP.** Tailwind CSS 4 is wired through PostCSS and imported in the root layout; shared colors, typography, responsive page surfaces, form controls, tables, keyboard focus, and reduced-motion handling apply consistently across the existing screens. Responsive sign-in was browser-checked; Playwright workflows pass.
- **Add the qualification-expiry CSV export to the MVP.** `/reports/qualification-expiry/export` returns a UTF-8 CSV for the complete current report using its privacy-minimized columns, UTC date window, and inactive-helper marker. CSV cells are escaped and formula-prefixed values are neutralized. Exports require Maintainer access and write a minimal export audit event; report record-read audits are retained. Unit, PostgreSQL integration, authorization E2E, and browser-download checks pass.
- **Build reusable qualification master data.** Maintainers manage fixed-field reusable definitions (name, optional category, retirement) at `/qualifications`. Helper assignments reference catalog definitions and retain independent date-only expiry dates. Existing free-text titles are mapped into definitions by case-insensitive trimmed name without changing assignment dates. Retired definitions remain visible on existing assignments and cannot be newly assigned. Qualification expiry behavior remains intact. Maintainer-only reads/writes are audited without definition or personal-data values; the specifically approved validity-date change/removal values are covered under the qualification-assignment controls item. Unit, PostgreSQL integration, and browser workflow coverage pass.
- **Build equipment master data and assignments.** Maintainers manage reusable types and individually tracked items at `/equipment`; items have Available, Assigned, In repair, and Retired lifecycle states and assignment history, with a PostgreSQL partial unique index enforcing one current helper per item. Services guard type retirement, active-helper assignment, and valid status transitions transactionally. Helper profiles show current equipment. Maintainer-only reads/writes are audited without values; unit, PostgreSQL integration, and browser workflow coverage pass.
- **Apply database migrations to dev and test.** All eight migrations (initial schema, authentication, helper registry, audit immutability, retention policy, organizations, qualification/equipment master data, and qualification-validity audit values) are applied. `prisma migrate status` verified both configured databases are up to date; existing qualification assignments and dates were preserved. Legacy `User`/`Role`/`Permission`/`Identity`/`AuditLog` rows remain untouched; no production or other target database was changed.
- **Keep qualification assignments fixed and make validity changes auditable.** Existing assignments show their catalog definition as read-only; updates accept only a valid-through date, unchanged dates do not create events, and Maintainers can remove assignments. Transactional row locking keeps the recorded previous date accurate; update/removal and old/new values commit atomically. The Maintainer audit table shows only the approved date/sentinel values. Integration and browser tests cover changed/unchanged validity, definition-change rejection, removal, and audit display.
- **Administrator account management.** `/admin/maintainers` supports creating a Maintainer, disable/enable, session revocation, authenticator reset, password reset, deletion, and Administrator grant/revoke (never leaving fewer than two verified Administrators); users change their own password at `/account/password`. All actions are audited and integration-tested; grant/revoke, deletion and password change are browser-confirmed. Playwright covers Administrator/Maintainer separation and immediate session revocation on disable. Not yet in e2e: password change, deletion, and grant/revoke.
- **Audit feature.** Events cover authentication/MFA/account/report/retention actions with transactional, fail-closed writes and reads (helper writes roll back if the audit event cannot be stored; sessions are deleted if their sign-in event cannot be stored). `audit_events` is append-only via a DB trigger; deletion is only possible for the retention job under `app.audit_retention`. A Maintainer-only paginated `/audit` view shows minimal actor/action/target/time metadata. A least-privilege runtime DB role (`scripts/sql/app-role.sql`) is documented and verified on the test database. Verified by integration and e2e tests. Still open: verify the role on the target database.
- **Administrator-maintained retention schedules and retention job.** `/admin/retention` records the approved inactive-helper and audit-log periods with a decision reference, approver and time (audited); the preflight now checks these records instead of env flags. `npm run retention:run` is a dry run by default, `--confirm` hard-deletes eligible inactive helpers (qualifications cascade, `HELPER_PURGED` id-only audit) or old audit events (privileged `RETENTION_DATABASE_URL`, trigger opt-in). `helpers.deactivatedAt` starts the clock. Integration- and e2e-tested; browser-confirmed. Scheduling examples (systemd/cron) are in the README. Still open: the organization actually approving periods and enabling the schedule.
- **Browser end-to-end coverage.** `npm run test:e2e` (Playwright, port 3100, `TEST_DATABASE_URL`) covers mandatory TOTP enrollment, rejected credentials, Administrator-created Maintainer creating helpers/qualifications and the expiry report, Administrator/Maintainer separation, immediate session revocation on disable, and recovery plus TOTP re-enrollment. It found and fixed a bug where framework `$ACTION_*` form entries made helper/qualification creation fail validation. Not covered: expiry-report boundary dates, password change, role grant/revoke and delete in the browser.
- **Requirements/design updated** for Maintainer deletion and self-service password change (requires current password + TOTP).

- **TOTP enrollment QR code:** the enrollment page shows a QR code in addition to the manual key (some authenticator apps reject the long manual key).
- **Manually verified in the browser:** sign-in with TOTP, password change with TOTP, and an Administrator granting themselves the Maintainer role, Administrator maintainer deletion, and the retention schedule page.

- **Authentication foundation:** Email/password sign-in, mandatory TOTP enrollment and verification, protected-route access controls, Administrator bootstrap, and production preflight are implemented.
- **Maintainer registry slice:** Maintainer-protected helper directory, profile create/update, qualification create/update, and the qualification-expiry report are implemented. The report uses the approved UTC date-window semantics and includes inactive helpers.
- **Initial validation and unit tests:** Strict helper/qualification validation, authentication policy/configuration coverage, and qualification-expiry boundary tests are present.
- **Read-only audit-log view:** Added Maintainer-protected access at `/audit`, displaying paginated actor, action, target reference, UTC event time, and the specifically approved old/new qualification valid-through values without fetching linked account or helper details.
- **MVP scope and key design decisions:** PostgreSQL, fixed helper profile fields, name-only directory search, UTC report boundaries, additive explicit roles, and deferred future features are recorded in `requirements.md` and `docs/TDD.md`.

## Explicitly out of this implementation plan

Helper self-service, tasks and task-based equipment checks, dynamic fields, exports beyond the MVP qualification-expiry CSV, missing-qualification reports, broader analytics, and a general-purpose configurable permission system are outside the approved MVP and next-delivery scope.
